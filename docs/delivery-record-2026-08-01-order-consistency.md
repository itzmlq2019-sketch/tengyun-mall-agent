# 交付记录：订单与库存一致性第一阶段

交付日期：2026-08-01

## 改动范围

- 商品服务新增以 `requestId` 为唯一键的库存扣减流水。
- 相同请求重复扣减时直接返回既有结果，不重复减少库存。
- 商品服务新增幂等库存补偿能力。
- 订单消费者以订单库中的 `request_id` 唯一记录作为最终幂等依据。
- 订单写入失败时请求商品服务补偿库存。
- 订单已存在或购物车清理失败重试时，只清理购物车，不重新扣库存。
- 商品服务新增库存流水 Flyway 迁移。

## 明确未改范围

- RabbitMQ Publisher Confirm、Return 和有限重试策略。
- 库存及死信管理接口的权限隔离。
- 真实 MySQL、Redis、RabbitMQ 环境下的故障注入测试。
- 全部服务的数据库初始化迁移。
- AI 接口和流式输出。

## 新增或变更测试

- 重复 `requestId` 不重复扣库存。
- 库存补偿恢复数量并更新流水状态。
- 已存在订单只执行购物车清理。
- 订单写入失败触发库存补偿。
- 购物车清理失败不触发库存补偿，也不在当前消费中重复扣减。

## 剩余已知风险

- 商品扣减成功但 HTTP 响应丢失时，设计上由商品侧 `requestId` 流水保证重试不重复扣减，但仍需真实网络故障注入验证。
- 库存补偿暂由订单消费者同步调用；补偿服务长期不可用时缺少独立补偿任务和告警。
- RabbitMQ 普通异常仍缺少明确的有限重试配置，可能发生反复重新入队。
- 商品缓存的延迟删除仍使用公共线程池。
- 库存扣减和补偿接口尚未限制为内部调用。

在真实中间件集成测试通过前，验收清单中的订单一致性发布阻断项保持未关闭。
