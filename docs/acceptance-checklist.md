# Tengyun 项目验收清单

本文档是项目“完成”的统一判定标准。未经实际验证的项目不得标记为通过；代码存在但没有测试证据，只能标记为“待验证”。

## 1. 状态与证据规则

- `[ ]`：未验证或未完成。
- `[x]`：已通过，必须在验收记录中附命令、结果和日期。
- `[!]`：确认存在阻塞问题，修复前不得发布。
- 自动化测试必须能在干净环境重复执行，不能只提供手工判断。
- 涉及 MySQL、Redis、RabbitMQ、Nacos 的功能必须有集成或端到端证据；单元测试不能替代外部依赖验证。
- 任何跳过项必须说明原因、影响和后续计划。

## 2. 发布阻断条件

出现以下任一情况，本次版本不得声明为“完成”或“生产可用”：

- 下单失败可能造成库存多扣、少扣或订单重复。
- 普通用户能够直接扣库存、查看死信或重投死信。
- 可以绕过网关伪造其他用户身份。
- RabbitMQ 消息丢失后接口仍报告成功，且没有补偿或追踪机制。
- 仓库不能初始化全部数据库。
- 仓库或日志中包含真实密钥、Token、密码。
- 必需测试失败，或关键测试因环境原因未执行。

## 3. 构建与基础质量

- [ ] Java 17 环境下执行 `mvn clean verify` 成功。
- [x] 所有模块均能独立启动，启动日志没有 Bean、数据库迁移或服务注册异常。
- [x] 单元测试全部通过，并保存测试数量与失败数量。
- [ ] 增加静态检查，至少覆盖编译警告、依赖漏洞和明显代码缺陷。
- [x] OpenAPI 文档能够生成，接口定义与实际请求格式一致。
- [ ] README 中的技术栈、启动方式和实际代码一致。

## 4. 用户与网关安全

- [ ] `/user/login` 是唯一无需认证的业务接口。
- [ ] 无 Token、过期 Token、错误签名 Token 均返回结构化 `401`。
- [ ] 网关会覆盖客户端传入的 `X-User-Id`。
- [ ] 下游服务不能从外部网络直接访问，或具备独立的服务间认证。
- [ ] 生产环境未设置 `JWT_SECRET` 时启动失败，不允许回退到固定默认密钥。
- [ ] 密码只允许使用 BCrypt 等安全哈希存储；明文兼容必须有迁移和移除期限。
- [ ] 库存扣减、死信查询、死信重投仅允许内部服务或管理员访问。
- [ ] CORS 使用明确的可信来源，不允许无条件放开所有来源。
- [ ] 日志、异常响应和 AI 输出不泄露密码、密钥、JWT 或内部配置。

## 5. 商品与购物车

- [ ] 商品不存在、已下架、库存不足时返回明确业务结果。
- [x] 库存扣减 SQL 在并发情况下不会产生负库存。
- [ ] 普通客户端不能直接调用库存扣减接口。
- [ ] 购物车中的商品名称和价格由商品服务确认，不信任客户端提交值。
- [ ] 相同用户和商品具有数据库唯一约束，并发加购不会生成重复记录或丢失数量。
- [ ] 商品缓存覆盖缓存穿透、热点 Key 并发回源和更新一致性测试。
- [ ] Redis 不可用时，商品核心查询能够按预期降级，且错误可观测。
- [ ] 延迟删除使用受控线程池或可靠任务机制，不依赖公共线程池裸任务。

## 6. 订单一致性与幂等

- [!] 库存扣减成功、订单写入失败时，库存能够自动恢复或保持可重试的预占状态。
- [!] 订单写入成功、购物车删除失败时，重试不会再次扣库存或重复创建订单。
- [ ] 同一 `requestId` 重复消费 2 次及以上，只产生一张订单并只扣一次库存。
- [ ] 同一消息在服务重启、网络超时和消费者异常后仍满足幂等要求。
- [ ] Redis 幂等键丢失或过期后，数据库唯一约束仍能防止重复订单和重复扣库存。
- [ ] 锁获取失败不会静默丢单，并有有限重试或可追踪失败状态。
- [ ] 商品不存在、库存不足、数据库异常、Feign 超时均有明确的状态迁移和补偿策略。
- [ ] 订单金额使用服务端商品价格计算，不信任客户端或 AI 提交的价格。
- [ ] 用户能够通过 `requestId` 查询异步订单最终状态，而不是只能看到“已受理”。

### 必须自动化的故障注入用例

- [ ] 扣库存前商品服务超时。
- [ ] 扣库存请求成功，但响应在网络中丢失。
- [ ] 扣库存成功后订单数据库写入失败。
- [ ] 订单写入成功后购物车服务失败。
- [ ] 消费完成后、消息确认前消费者进程退出。
- [ ] Redis 在写入或读取幂等键时不可用。
- [ ] 两个消费者同时处理同一商品、不同订单。

每个用例必须同时断言：订单数量、库存变化、购物车状态、消息最终位置和可观测告警。

## 7. RabbitMQ 可靠性

- [x] 生产者启用 Publisher Confirm，并处理 NACK。
- [ ] 生产者启用 Return 或等效机制，处理无法路由的消息。
- [x] 只有 Broker 确认消息成功后，接口才返回明确的“已受理”结果。
- [x] 消费失败采用有限次数、带退避的重试策略，不允许无限热循环重入队。
- [x] 超过重试次数的消息稳定进入死信队列。
- [ ] 死信记录包含 requestId、失败阶段、根因、重试次数和时间。
- [ ] 死信重投具有管理员权限、操作审计和重复重投保护。
- [x] RabbitMQ 重启后，交换机、队列和持久化消息仍然存在。

## 8. AI 导购

- [!] `/agent/chat/stream` 实现真实的流式输出；若仍为单次响应，应取消 SSE 命名和媒体类型。
- [!] 可能触发加购或下单的聊天接口使用 POST，不通过 GET 参数执行写操作。
- [ ] 下单工具执行前需要用户明确确认商品、数量和金额。
- [ ] 工具调用中的用户 ID 始终取服务端身份上下文。
- [ ] 模型无法调用白名单外工具，也不能通过参数越权操作其他用户。
- [ ] 工具可以连续调用多轮，并具有最大轮数和超时限制。
- [ ] 提示词注入测试覆盖中英文、编码变形和间接注入场景。
- [ ] AI 调用设置连接、响应和总耗时超时，并有取消机制。
- [ ] 审计记录采用模型返回的真实 usage；估算值必须明确标识为估算。
- [ ] AI 服务或模型不可用时，商品、购物车和订单基础 API 仍可独立工作。
- [ ] README 明确说明实际使用 Spring AI 还是直接调用 OpenAI 兼容 API。

## 9. 数据库与迁移

- [!] 为用户、商品、购物车和 AI 审计库补齐版本化迁移脚本。
- [ ] 空数据库启动后能够自动创建全部表、索引和约束。
- [ ] 迁移可在已有数据库上安全执行，重复启动不会破坏数据。
- [ ] `request_id`、用户名、购物车用户商品组合等唯一约束符合幂等要求。
- [ ] 金额字段精度、时间字段时区和字符集在所有服务中统一。
- [ ] 提供最小可用的本地测试数据初始化方式，不包含真实用户或秘密。
- [ ] 数据库备份恢复后执行一次完整下单链路验证。

## 10. 配置、部署与可观测性

- [ ] `env.example` 包含所有必需变量且只使用安全占位值。
- [ ] 生产必需配置缺失时快速失败，不使用开发默认地址或默认密钥。
- [ ] Redisson 使用统一的 Redis 环境变量，不能硬编码 `127.0.0.1:6379`。
- [ ] Feign 配置连接超时、读取超时、重试边界和熔断策略。
- [ ] 所有请求具有 traceId，订单 requestId 能贯穿网关、MQ 和下游日志。
- [ ] 关键指标至少包括登录失败、下单受理、下单成功、补偿、重试、死信、AI 延迟和 AI 错误。
- [ ] 健康检查区分存活状态与就绪状态，并覆盖 MySQL、Redis、RabbitMQ、Nacos。
- [ ] 启停脚本不依赖开发者机器上的固定 Maven 路径。
- [ ] 只有网关端口对外开放，内部服务端口由网络策略隔离。

## 11. 最终端到端验收

- [ ] 新环境可依据 README 从零完成部署。
- [x] 用户登录后可查询商品、加购、查看购物车、提交订单并查询最终状态。
- [ ] AI 可以查询商品、推荐、加购，并在确认后下单。
- [x] 50 个以上并发订单不会出现负库存、重复订单或无记录库存扣减。
- [ ] 服务或中间件短暂故障恢复后，没有静默丢失的已受理订单。
- [ ] 非管理员无法访问库存管理和死信管理能力。
- [ ] 运行自动化冒烟、回归、集成与故障注入测试，结果全部通过。
