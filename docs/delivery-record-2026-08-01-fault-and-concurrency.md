## 3. 50 并发库存测试发现的问题

第一次有效并发测试结果：

```text
并发请求: 50
成功扣减: 26
库存: 50 -> 24
有效流水: 26
补偿后库存: 50
测试数据清理: 完成
```

库存没有超扣，但有 24 个请求失败。原因是新 `requestId` 使用了：

```sql
SELECT * FROM product_stock_deduction
WHERE request_id = ?
FOR UPDATE
```

MySQL 在记录不存在时对唯一索引间隙加锁；多个不同 `requestId` 并发插入时产生锁冲突或死锁。

## 4. 修复

- 新请求先执行非锁定查询。
- 新流水在库存扣减事务中直接插入，依靠 `request_id` 唯一索引处理同请求竞争。
- 只有已存在流水的状态转换继续使用 `FOR UPDATE` 行锁。
- 同一请求并发插入失败时，该事务中的库存扣减会随事务整体回滚。

## 5. 修复后真实并发复测

结论：50 个并发库存请求全部成功，库存未变为负数，流水数量与库存变化一致；补偿后恢复原库存。
